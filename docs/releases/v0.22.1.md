Fleet commands work again when the default inventory is a symlink to an inventory kept elsewhere.

### Fixed
- With `~/.config/rootfiles/fleet.yaml` symlinked to an inventory in another folder, every `rootfiles fleet` command run without `--inventory` failed with "reading config ...: no such file or directory", and the controller's `status`, `doctor` and `monitor` could not read the inventory, because relative `config:` paths were looked up next to the link. They now resolve next to the file the link points to. (#193)

### Action needed
- Update the fleet controller with `rootfiles update` on macOS, or `sudo rootfiles update` on a Linux controller. The fix runs only on the controller, so hosts can stay on v0.22.0; to keep versions aligned, run `rootfiles fleet update --all --version v0.22.1 --yes`. (#194)
